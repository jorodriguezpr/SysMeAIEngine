Training always runs on CPU (see the GPU card above for why — DirectML was tried and rejected). Rows beyond "Max rows" are representatively sampled — spread evenly across every source file — so a large folder still finishes in a practical time instead of running for hours. At the default 2000 rows with gpt2, expect roughly an hour on this hardware — measured, not estimated; your mileage will vary by CPU. qwen2.5-0.5b-instruct measured ~41x slower than gpt2 per row (0.014 vs 0.575 samples/sec) — at 2000 rows that's over a day, so drop Max rows to 50–100 unless you're deliberately running it overnight.

Evaluate a RAG corpus

Measures whether retrieval finds the right passage, using questions generated from a held-out sample of the corpus's own chunks (no labeled eval set needed). first_sentence queries with a sentence copied from the chunk; keywords with 6 exact words from it (no sentence). Keywords is a lexical test: near-trivial for tfidf, hard for semantic -- measured on aprocrifos-v2: tfidf hit@1 1.00 vs semantic 0.05. Compare methods on the same mode; hit@1/MRR separate results that recall@k scores the same. Optionally also scores a model's RAG-grounded answers (slow: one real generation per question).
